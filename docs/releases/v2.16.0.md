# brgr v2.16.0 — Herdr finally sees your workers

Claude workers used to show up in Herdr as nobody. No status, no name, and their pane stuck around after you accepted. Fixed.

Also fixed:

- The trust dialog getting pressed twice.
- A dead network getting reported as "go answer this screen".
- Three results finishing together and two of them waiting in line.

New:

- A board you can open anywhere.
- Worker counts in your status line.
- Two worker columns, or a row of workers under the head.
- A switch for where Claude models are allowed to run.

It's a minor because one default changes and two settings can't be read by 2.15.

> **From the maintainer:** Expect more from here on. brgr is now the main tool I use for my day-to-day work, and it's perfect.

## Read this before upgrading

- **Claude models only run through Claude Code now.** `claude-route` defaults to `claude-code-only`. If you run Claude models on OpenCode or anything else (aliases count), brgr refuses before starting. It won't quietly reroute. Want the old behavior?

  ```sh
  brgr config set claude-route any
  ```

  `brgr config check` lists every alias and default this would block.
- **Going back to 2.15? Turn these off first.** With `worker-placement = below` or `claude-route = any` set, 2.15 can't read `config.toml`.
- **Status line `--workers`:** run `brgr integrate claude install --context` without it before downgrading. Otherwise the old brgr thinks the flag is part of your own status line command.
- **Reinstall the skills** so your agents know the new rules: `brgr integrate claude install`, `brgr integrate codex install`.

## What's new

### Herdr finally sees your workers (#411, #403, #404)
brgr launched Claude Code by its versioned path, so the process was literally named `2.1.325`. Herdr had no idea it was Claude. Now the worker starts with `argv[0]` set to its harness kind. Same verified binary, same digest check.

- Claude workers show `idle`, `working` and `blocked` like everyone else.
- The sidebar shows `claude-1cf44e8d`, not a wall of `claude`.
- Accept or reject and the pane closes and the worktree goes away. No more closing them by hand.

### Screens get answered once, and only when it's safe (#402, #416)
- brgr remembers what it answered for the whole run, every stage. The trust prompt never gets pressed twice.
- No key is pressed until Herdr has actually picked up the worker. If a press only half landed (cursor moved, Enter lost), brgr sends the missing key right away instead of sitting there for 30 seconds.
- New answers: OpenCode's web search prompt gets Esc, never "Allow". Claude Code's LSP plugin offer gets "No, not now", never "Yes, install".
- Debugging a screen? Set `BRGR_SCREEN_TRACE=1`. It logs a digest of the screen, never the text.

### A dead network isn't a question (#417)
Lose the model provider and brgr now recognizes the harness's own retry/error screen and tells you straight: provider or network problem, here's the line. Covers OpenCode, Claude Code, Codex, Cursor and Devin. brgr doesn't press anything. The worker gets 10 minutes to recover instead of dying after 3. If it still dies, the reason says why.

### Results arrive together (#407)
Several workers finish at once? You get one `brgr_completions` notice the next time you're idle, failures included. A single result looks exactly like before.

### Watch everything
- **`brgr tui` (#413):** read-only live board in any terminal. Shows your session's tasks by default, with model and alias columns. The Herdr plugin board uses the same code now.
- **Status line (#410):** `brgr integrate claude install --context --workers` adds `brgr ⚙3 ✓1 ✗0 ?1`, meaning running, waiting on you, failed, asking you. It reads one tiny file. It never touches the database.

### Lay out workers your way (#409, #414)
- `adjacent` fills a second column before opening a tab, if the area is wide enough.
- `worker-placement below` puts workers in a row under the head. Run several heads in one tab, each with its own row.

### You decide where Claude runs (#415)
"Claude goes through Claude Code" used to be a line in a skill file. Now it's a setting brgr enforces. The Herdr host bridge can't change it.

## Smaller stuff

- `brgr harness list`: id, executable, version, health (#405).
- `harness add` doesn't need `--workspace` or `--prompt` anymore. brgr makes its own scratch repo, cleans it up, and keeps your global git hooks out of it (#406).
- GJC is back, tier 3 (#408).
- Command Code installed as `cmd` or `index.mjs` gets recognized. Unknown names now list what brgr does know (#429).
- The board's PROJECT column shows the repo, not a task id (#428).
- No more walls of `kill: No such process`. Stopping a worker only signals processes it can verify (#418).
- Running the tests inside an agent session doesn't break six of them anymore (#412).

## Known limits

- `below` gives you one row. When it's full, the next worker opens in a tab.
- `brgr tui` is read-only for now. Navigation, settings and replying to workers come later in 2.16.
- Provider detection knows the error text of the harness versions we checked. New wording needs a new rule.
